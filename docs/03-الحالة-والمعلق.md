## ما اكتمل ونُشر (بالترتيب الزمني تقريباً)

المشاريع والمراحل وجداول الكميات والمرجع الفني → المهام والطلبات → المستخلصات ودور المالية → التقارير بفترة زمنية ومنشئ مخصص → التقارير الفنية والمحاضر بالصور → المستندات والمخططات والاعتمادات → الإشعارات (جرس + Web Push + ملخص صباحي/مسائي) → إعادة التصميم v2 (قائمة جانبية، ثيم فاتح، ⌘K) → الأداء والإنجازات (تلقائي بلا تقييم يدوي) → المهندس ينشئ مشاريعه ويعدّلها فقط + ربط 17 مشروعاً بالمهندسين تلقائياً → المشروع بعد «استلام ابتدائي» منتهٍ → دور الإداري → صفحة «يومي» → حقول المبالغ الدقيقة → فاحص جودة البيانات → الإعدادات من الواجهة → تصدير Excel → نسخ احتياطي أسبوعي → أوامر التغيير والتمديدات مع مزامنة العقد → الإغلاق والضمان وتقييم المقاول والدروس → **الجدول الزمني والمعالم** (update30/31) → **إعادة بناء التحديات والمخاطر** (update32) → **الحركة والصقل** (update33) → **بطاقات ونماذج الجوال** (update34) → مستندات التسليم (update35) → **التقرير التنفيذي برابط** (update36): من صفحة التقارير زر «نشر رابط للإدارة» يُنشئ إصداراً مجمّداً (`shared_reports`) برمز عشوائي وصلاحية ورمز دخول اختياري؛ الصفحة العامة `r.html?t=…` تعمل بلا حساب وبطبقتين (ملخص تنفيذي ثم ورقة تفاصيل عند النقر على مشروع أو تحدٍ)؛ زر «أرسل ملاحظة» يصل كإشعار `exec` ويُدار من «الروابط المنشورة».

## قرارات مهمة يجب احترامها

- نسبة الإنجاز: لكل مشروع مصدر `progress_mode` = `manual` (افتراضي، الوضع الحالي) أو `schedule`. لا تُلغِ الإدخال اليدوي؛ التحول تدريجي بقرار المستخدم لكل مشروع.
- التحديات: لا تُغلق وفيها مهام مفتوحة؛ التكليف الحقيقي عبر المهام (المهام ينشئها admin فقط)، والمهندس يضيف متابعات.
- الأداء: رصد لإثبات الجهد لا للتقييم؛ لا طبقة تقييم يدوي ولا مجاملات. لوحة الشرف مطفأة افتراضياً.
- الإشعارات الخارجية (واتساب/بريد/Slack) مؤجلة بقرار المستخدم.
- دور المقاول مؤجل.
- الاستضافة تبقى GitHub Pages مجانية؛ الدومين يُشترى فقط (توصيتنا Cloudflare أو Namecheap، ويفضَّل سؤال تقنية المعلومات بالتجمع عن نطاق فرعي رسمي).

## نُشر في update42 — جداول كميات بالمقطوعية (Lump-sum)

- **قاعدة البيانات** `0020_boq_free_lines.sql`: `boq_lines.kind` (`ref` من المرجع | `free` بند حر) مع `title/descr/unit/div_code` و`variant_code` صار اختيارياً؛ `boqs.pricing` (`unit`|`lumpsum`) و`boqs.hide_prices` (نسخة طرح بلا أسعار). الملاحظات العامة تُخزَّن في `boqs.notes` الموجود أصلاً.
- **قائمة بنود المقطوعية** `site/js/lumpsum.js`: 33 بنداً متعارفاً عليها في 6 مجموعات (عامة وتحضيرية، معمارية وتشطيبات، كهربائية وتيار خفيف، ميكانيكية، خارجية، تشغيل وتسليم) بأكواد `LS-01..LS-33` ووصف طرح جاهز لكل بند، و4 قوالب (مدخل رئيسي، تأهيل عام، دورات مياه، واجهات وموقع) وملاحظات عامة معيارية `LS_DEFAULT_NOTES`. لإضافة بند للقائمة: أضف سطراً `I('LS-34', 'العنوان', 'الوصف')` في المجموعة المناسبة.
- **الواجهة** `site/js/boq.js`: زر «☰ بنود المقطوعية» (منتقي بمجموعات وبحث وقوالب وتحديد الكل، يُظهر «موجود» للمضاف سابقاً، وخياران: تسعير مقطوعية + إخفاء الأسعار، وإضافة الملاحظات المعيارية إن كانت فارغة) وزر «＋ بند حر / مقطوعية» (عنوان، وصف، وحدة من `UNITS`، كمية، سعر اختياري، شعبة للتجميع). البنود الحرة تُرقَّم `L-nn` تحت «بنود المقطوعية والبنود العامة» وتُعدَّل بـ ✎. بطاقة «ملاحظات عامة» تظهر فوق الجدول. عند `hide_prices` تختفي أعمدة الأسعار والمجاميع ويظهر شعار «نسخة طرح». إعدادات الجدول: طريقة التسعير + إخفاء الأسعار + الملاحظات.
- **التصدير** `site/js/excel.js`: البنود الحرة تُصدَّر بعنوانها ووصفها وكودها؛ الملاحظات العامة في صف مظلل فوق الجدول؛ في المقطوعية يصبح العمود «المبلغ المقطوع (ر.س)» وتتغير التعليمات؛ مع `hide_prices` يُصدَّر ملف الطرح فقط (بلا الورقة المسعّرة)؛ ورقة المواصفات تتجاهل البنود الحرة وتُحذف إن لم يبق بند من المرجع.
- **المحاكي** `scratchpad/qa_ls.js` يختبر المسار كاملاً (مشروع جديد → جدول → قالب → تعديل → تصدير). ملاحظة: مكتبة ExcelJS تُحمَّل من cdnjs ولا يصلها الصندوق؛ في الاختبار تُوجَّه إلى نسخة محلية.
